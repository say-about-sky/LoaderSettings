# Quick Actions · 快捷操作(长按移动军队 + 双击按住框选 + 启用快速国策)

给《Age of History 3》(电脑版 / 安卓版)新增两个触摸快捷操作,由顶部那个按钮统一开关。

| 功能 | 操作 | 平台 |
| --- | --- | --- |
| **长按移动军队** | 选中军队后,**长按地块** ≥450ms → 军队行进(对标电脑版右键) | 安卓(桌面端始终生效) |
| **框选军队** | **单指轻点两下、第二下按住不放再拖** → 划出选框选中框内军队/省份 | 安卓 |
| **启用快速国策** | 在国策(任务)树上**轻点一次**(原生弹窗)→ **再点一次同一个国策** = 直接替玩家按掉弹窗里的确认(原版 `InGame_Event` 与 MOD 的「开始国策」窗口 `InGame_StartFocus` 都支持) | 安卓 |
| **设置面板** | **按住顶部按钮 1 秒** → 按钮下方弹出「修改快捷方式」(原生 UI 风格),内含三个开关:**「启用快捷操作」「启用快速国策」「反转框选与移动」** | 安卓 |

## 两种手势模式(可在面板里反转)

```text
                      按住不动(≥450ms)            按住后拖动
   默认(反转=关)       移动军队到该点               平移地图
                      双击第二下按住 120ms 再拖 → 框选
   反转(反转=开)       双击(第二下不必按住) → 移动军队   框选(按住 450ms 后真正拖 ≥60px)
                      普通按住不拖动 → 什么都不做(松手也不会选中地块)
```

**移动军队的判定**:全程偏移 ≤100px(≈1~1.5cm,手机长按时手抖是常态)且开关打开;
默认模式要求**按住 ≥450ms**,反转模式要求**是双击的第二下**(不要求按住 —— 选中的军队在场时接管双击,
没选中军队时双击仍然走游戏原生的"缩放复位"✓)。拖动过(>100px)= 平移地图或框选 → 不移动。

⚠ 反转模式下"压住第一下点击"的必要性:双击的**第一下**会被游戏原有逻辑当作普通点击,而普通点击会重新选中对象
(点到没军队的地块 → `activeArmySize` 变 0)→ 第二下的移动就失效了。
所以已选中军队时,第一下的点击会被**压住很短一段时间**(`DEFER_CLICK_MS = 130ms`):
- 第二下在 130ms 内到达(快速双击)→ 丢弃这次点击(选中不被改)→ 移动军队 ✓;
- 130ms 内没来 → 原样补发这次点击(对象切换只多等 130ms,基本无感)→ 且这一次"双击"不再是移动手势
  (避免"慢双击"变成"先选对象又行军"的怪行为)。

> 两个窗口是分开的:双击**识别**窗口 240ms、压住点击的**等待**窗口 130ms;
> 想更灵敏可调小 `DEFER_CLICK_MS`,想更容易双击成功可调大(代价就是对象切换多等一点)。

⚠ 反转模式下"按了够久但没拖动"的抬起会被**吞掉**(不作为普通点击),避免误选地块;拖动过(平移地图)不受影响。

⚠ 反转模式下"长按框选"必须在按满 450ms 后**禁止平移地图**({@code shouldBlockMapPan}):
框选要等位移达到 60px 才真正开始,若不拦截,最初那 60px 拖动会把**视角带偏一小段**(实测)。
拦截后:框选全过程视角不动,而**直接拖动平移**(没按满 450ms、或按满前就拖开)完全不受影响。

**双击判定带位置/时间约束**:两次轻点间隔 ≤240ms(贴近安卓系统双击超时)、落点相距 ≤120px,
否则视为两次独立点击(避免"轻点选中军队 → 到别处长按目的地"被误判成双击而丢掉那一次长按)。

## 真机诊断(默认关闭;出问题再打开)

代码里有一个总开关:`QuickActionsState.DEBUG_OUTPUT`(**默认 `false`;1.4.3 测试包曾临时置 `true` 用于真机调试国策,1.4.4 起已恢复关闭**)。
改成 `true` 重新构建/出 dex 后,按住顶部按钮就会弹出游戏原生悬停提示,内容为:

```text
启用快捷操作 · 长按 1 秒打开设置 · 1.4.0
反转模式:双击=移动军队 · 长按拖动=框选
当前: 按住 320ms 位移 12px 阈值=450ms/100px
上次: dur=42 mv=0 dbl=1 inv=1 en=1 | valid=1 ptr=0 ig=1 cp=0 army=3 => move=1
```

- `mv` = 本次长按过程中的最大位移(手抖多少一目了然);`en`=开关、`inv`=反转、`dbl`=是否双击第二下、
  `ig`=在游戏中、`cp`=行进选目标模式、`army`=选中军队数、`move`=最终是否移动;
  `当前:` 行只在"确实有一个地图长按正在判定"时显示;
- 开关打开时还会:把关键结果弹成**游戏自带提示框**(红色文字 + 小图标,与任务系统的「要求未满足」同款 ——
  不用安卓系统 Toast:部分系统会限制/静默失败)、并把决定写入日志(`LongPressMoveArmy: 上次: ...`);
  提示标题里会附上构建标记 —— **看不到构建标记 = 手机上跑的还是旧补丁 dex**(需要重新合并/安装);
- 开着调试时,「启用快速国策」的每一步也会弹提示框:已武装,再点一次=确认 / 已确认(开始国策) /
  已确认(事件弹窗) / 弹窗未出现,稍后补点 / 补点确认成功 / 武装解除(弹窗已关) /
  开始窗口无法自动确认,交还原生 / 弹窗无法自动确认,交还原生 / 没有任务挂起,交还原生。

- 三个开关(启用快捷操作 / 启用快速国策 / 反转框选与移动)都位于「修改快捷方式」面板,**按住顶部按钮 1 秒**即弹出;
- 反转只影响**框选**的触发方式:默认=双击第二下按住 120ms 再拖;反转=按住 450ms 再拖(不必双击);
- **移动军队在两种模式下都是「按住 450ms 不拖动再松手」**;
- 状态持久保存,重启后保持。

## 设置面板(长按按钮 1 秒)

- 触发:**按住**右上角那个快捷开关按钮 **1 秒**(期间手指基本不动),面板弹在按钮正下方(右对齐,自动避免出屏);
- **计时按游戏帧来算**(不是墙上时钟):这个判定只能靠每帧轮询 `drawText`,若直接用 `System.currentTimeMillis()`,
  后期卡顿(单帧变长,如一帧 200ms)会导致"要按 1 秒多才弹"。现在改成:
  ①按住时长按**游戏帧时间**(`getRawDeltaTime()` 逐帧累加);
  ②判定时**提前一帧**(已累加时长 + 本帧时长 ≥ 阈值即成立)。
  于是实际按住时长总落在 **[1s − 一帧, 1s]** 区间内 —— 5fps 到 120fps 都不会超过 1 秒。
  (地图手势的计时与之不同:它们都在**触摸事件回调**里按输入事件时间戳算,天然与帧率无关。)
- 外观:直接用游戏原生控件搭 —— 面板 = 原生 `Menu` + `MenuTitle`(与「游戏设定」同款标题栏/边框),
  开关行 = 原生 `ButtonGame2` 的 checkbox 行(**与「设置 → 边缘滚动」同款**:左侧一条渐变表示开/关,点击切换);
- 长按打开面板后**这一次触摸会被整段吞掉**(按下+移动+抬起都不会传给地图/按钮),不会顺手把开关切回去;
- 点面板外任意处关闭(**同样整段吞掉**):面板没有关闭按钮(点任意区域即可关,不必再画一个 X);
  ⚠ 这里必须吞掉**整段**触摸 —— 只吞抬起的话,移动会照常传给 `MapTouchManager.actionMove`,
  而这次按下的 `actionDown` 已被吞掉 → 地图平移锚点(`iStartMovePosX/Y`)还是**上一次**手势的值 → **视角跳变 + 地图像平移**;
- 按住按钮时的提示文字已改为「启用快捷操作 · 长按 1 秒打开设置」(原本显示「选择多个军队」);
- 桌面端该按钮仍是原生「图钉」,不做任何拦截。

## 框选手势(单指,默认模式)

```text
轻点          轻点第二下,按住≥120ms        拖动          抬起
 ↓                ↓                       ↓            ↓
抬起记一笔     进入原生框选(出现选框)    游戏原生维护   原生结算选中
```

- 「轻点」定义:按住 ≤260ms 且位移 ≤24px;
- 两次轻点间隔 ≤**200ms** 才算双击(≈ 游戏自身的双击窗口 175ms,略放宽);
- 第二下**按住 ≥120ms** 才进入框选:既贴合"按住"这个动作,也能避免"轻点后立刻拖动地图"被误判;
- 按满时间之前就拖开(位移 >24px)→ 放弃框选,照常平移地图;
- 第二下转眼就抬起、几乎没拖动(选框边长 <12px)→ 撤销选框,把这一下交还给游戏(等同普通双击,缩放复位照常);
- 整个框选**完全复用游戏原生机制**,手感与原来那个「选择多个军队」按钮点出来的单指框选一模一样。

> 手感不对只需调 `QuickActionsState` 顶部 5 个常量:
> `TAP_MAX_MS` / `TAP_SLOP_PX` / `DOUBLE_TAP_MS` / `BOX_HOLD_MS` / `MIN_BOX_PX`。

## 长按移动的防误触(选中军队后双指缩放不再误触)

安卓端能让军队移动的入口只有 `MapTouchManager.actionUp` 里的 `setProvinceID_PPM`
(nullptr原生只在 `button==1` 即右键时调用,而安卓的 `button` 永远是 0),再加上我们的长按注入。
因此只要长按判定够严就不会误触:

- **任何「第二根手指」活动(按下或移动)立即取消本次长按判定** —— 缩放手势自始至终不可能触发移动;
- 长按位移判定改用**过程中与按下点的最大偏移**(而不是「抬起点与按下点的距离」),
 于是「拖出去再拖回来」(净位移≈0)也不会被当成没动过;
- 进入框选手势时同样取消长按;菜单吃掉的按下也会取消长按。

## 顶部按钮的交互(兼顾两类玩家)

| 操作 | 效果 | 面向 |
| --- | --- | --- |
| **点一下** | **原版行为**:武装一次"一次性框选"(下次在地图上按下即开始框选,用完自动解除) | 习惯原版的玩家 |
| **长按 1 秒** | 弹出「修改快捷方式」面板(三个开关都在里面切换) | 想用新玩法的玩家 |

- 默认(新装/未切换过)= 全部功能**关闭**,即纯原版手感 + 按钮的"一次性框选"原版行为;
- **总开关只在面板里切换**:按住按钮 1 秒 → 点「启用快捷操作」行;
- 按钮图标**金色半透明高亮** = 快捷操作已开启(与原版"框选已武装"的高亮同款绘制,判定的是我们的开关);
- 按住按钮能看到交互说明(点一下 / 长按 1 秒,以及开启"快速国策"后的额外提示)。

> ⚠ 1.3.0 曾用"快速双击按钮"切换开关,实测**不可靠**:双击的第二下会被原版"取消框选"逻辑吃掉
> (原生按钮的 actionElement 就是"取反 selectArmiesMode",第一下武装、第二下取消),
> 还会与菜单按压状态互相干扰。1.4.0 起已移除 —— 按钮点按**完全交还原生**
> (`Touch.actionUp` 不再接管按钮抬起),开关只在面板里改。

## 启用快速国策(点一次,再点一次同一个 = 确认)

- **开关**:面板里「启用快速国策」行(默认关,持久保存);
- **交互**:国策树上**轻点一次**某个国策 → 原生行为(弹出"开始国策"窗口,选项按钮要自己点);
  **弹窗出现后,再点一次同一个国策**(同一位置、**4 秒**内)→ 直接把窗口里的确认选项点掉;
- 为什么不用"快速双击":实测点国策会让页面关闭/刷新,第二下根本赶不上 240ms 的双击窗口 ——
  所以改成"位置配对 + 长窗口"(双击的第二下只要落在同一位置,同样走这条确认路径);
- **只认国策(任务)事件**:普通剧情事件窗口(0~5)完全不碰,不会替你选剧情;
- **单选项窗口直接点掉**;万一某个国策弹窗有多个选项,只点带"确认/开始/接受"字样的那个,
  认不准就什么都不做(不替玩家做选择,这一下也不再拦);
- "第一下"要求是**国策界面上的干净轻点**(没拖动、没长按)—— 拖动是在滚国策树;
  这样"再点一次"只可能发生在刚点过的那个国策上,不会在别处误确认;
- 第二下比弹窗来得还快(弹窗是延迟一步创建的):若任务**确实已挂起**(点节点成功),
  会先吞掉第二下、随后 30 帧内补点确认;若其实没挂上(比如条件不满足只弹了报错)则完全交还原生;
- 弹窗开过又关了(比如你自己点了选项或确认)→ 武装自动解除,之后点同一位置不会再有特殊行为;
- **两种"开始国策"窗口都支持**(安卓 dex 逆向 + RainfallEvent 开源代码确认):
  - **原版任务事件窗口** `InGame_Event`(任务的 `event.focusDura ≤ 0` 时走这条):点树节点会
    `runMission` → `addActiveEvent(999/1000)` → 延迟一步弹事件窗口;我们找该窗口并调用选项按钮的
    `actionElement()`(**与手指点一下完全等价**,结算/关窗/右侧面板刷新都走游戏原代码);
  - **RainfallEvent 国策系统的「开始国策」窗口** `InGame_StartFocus`(任务带周期 `focusDura > 0` 时,
    暮色黄昏/世界大战等 MOD 走这条,且**不会**产生 999/1000 活动事件 —— 1.4.2 之前因此检测不到):
    窗口实例在 `MenuProxy.getMenus().get(IN_GAME).get(IN_GAME_NUKES)` 槽位;我们直接反射调用它 public 的
    `confirm()`(即窗口里 Confirm 按钮的动作:`focusData.startGoal(...)` + 刷新信息面板 + 关窗);
  - 不需要读任何 txt/json 脚本(任务事件脚本只负责"挂载判断与收益",确认按钮是游戏 UI 本身)。

## 实现方式(逆向要点)

安卓端触摸事件都经过 `Touch`(由 `AA_Game$1` 这个 libGDX `InputAdapter` 转发):

| 我们覆盖/注入 | 做了什么 |
| --- | --- |
| `Touch.actionDown` | ①保留**原版**「点一下按钮武装的一次性框选」分支(`Touch.selectArmiesMode` 原样消费);②面板开着时点面板外 = 关面板并把这次触摸**整段**吞掉;③国策侧:快速双击时接管(点掉"开始国策"窗口的确认选项并吞掉第二下);④其余地图按下走我们的快捷手势状态机 |
| `Touch.actionMove(int,int,int)` | ①本次触摸若已被整段吞掉 → 直接 return;②反转模式下按住满 450ms(框选候选)→ **不再平移地图**;③单指移动时判断是否该进入框选;④第二根手指在动则取消长按判定 |
| `Touch.actionUp`(HEAD 注入,可取消) | ①整段吞掉的触摸 → `cancel()` 抬起;②记录轻点(地图双击用)与国策侧轻点(双击配对用);③框选几乎没拖动则撤销选框;④反转+已选中军队时压住双击第一下的原生点击。**不再接管顶部按钮的抬起** —— 按钮点按完全走原生 |
| `MapTouchManager.actionDown/actionUp` | 长按移动:需按住 ≥450ms 且**最大偏移** ≤100px(`QuickActionsState.canMoveArmy`,两种模式同一条规则);多指/菜单按下都会取消长按。判定详情写日志;`DEBUG_OUTPUT=true` 时还会弹 Toast / 写进按钮提示,便于真机排查 |
| `MapTouchManager.drawSelectMode` | 每帧一次(`QuickActionsState.tick()`):按钮长按计时基准、补发压住的地图点击、快速国策"等弹窗"补点确认 |
| `ButtonTopOutliner.drawText`(RETURN 注入) | 该按钮每帧都会走这里 → 借它做「按住按钮 1 秒」的计时(按游戏帧时间累加 + 提前一帧判定;按下的那一点还必须落在按钮矩形内),成立则弹出设置面板 |
| `ButtonTopOutliner.buildElementHover`(HEAD 注入,可取消) | 把按住按钮时的提示文案换成「启用快捷操作 · 长按 1 秒打开设置」+ 交互说明行(开启"快速国策"时多一行提示);`DEBUG_OUTPUT=true` 时追加诊断行(手势对照/实时按住/上次判定/快速国策状态)与构建标记;其它继承该基类的按钮不受影响(按运行时类名过滤) |

双指缩放**完全不碰**(保持原生)。

### ⚠ 为什么只改 `Touch`、`MapTouchManager`、`ButtonTopOutliner`

luminosity2 的 Mixin 会把整个目标类替换成「**PC `game.jar` 里的版本** + 改动」,
因此**只能改安卓与 PC 逐字节一致的类**(用 `dexdump`+`d8` 逐方法比对指令数确认):

| 类 | 结论 |
| --- | --- |
| `Touch`、`MapTouchManager`、`ButtonTopOutliner` | 完全一致 → 可改 |
| `AA_Game$1` | `keyDown` 被改过 → **不可改** |
| `InGame$13` | 安卓端是另一个按钮(`ButtonTopSpeed` 子类) → **不可改**;真正的开关按钮在安卓端叫 `InGame$14` |

> 踩坑记录:第一版误把 `InGame$13` 当开关按钮替换,进「选择国家」时崩溃
> (`NoSuchMethodError: InGame$13.<init>(LInGame;III)V`) —— 匿名内部类编号在两端会整体偏移。
> 比对脚本留在 `.tools\cmp`,新增 Mixin 目标前请先跑一遍。

## 生成安卓 dex 补丁(patch 模式)

> ⚠ 必须用 **JDK 11+** 运行 loader:loader 的 d8 子进程会调用系统 `java`,
> Windows 会在"父进程 EXE 所在目录"优先查找 —— 用游戏自带 `jre\bin\java.exe`(Java 8)运行 loader,d8 会因版本过低失败。

> **一键版:双击 `HotPluginLoader\build-dex.bat`** —— 自动挑 JDK 11、显示将要打包的 jar 及其构建时间、调用 loader 生成 `HotPluginLoader\out\game.dex.zip`;想换 JDK 可先 `set JAVA11=<jdk11>\bin\java.exe`。

```powershell
Start-Process -FilePath "<JDK11+>\bin\java.exe" `
  -ArgumentList '-jar','<游戏根>\loader-1.6.0.jar','--launch-mode','patch','--patch-config','<游戏根>\PatchBuild\patch.json' `
  -WorkingDirectory '<游戏根>\PatchBuild' -Wait -NoNewWindow
```

- 配置:`PatchBuild\patch.json`(`plugins` 里的 jar 文件名要跟 `build.gradle` 的 `version` 一致);
- 产物:`PatchBuild\game.dex.zip`(`classes.dex`,约 44KB)。

### 补丁 dex 内容(15 个类)

注入版游戏类:`Touch`、`MapTouchManager`、`ButtonTopOutliner`;
插件类:`QuickActionsState`、`QuickMissionConfirm`、`LongPressState`、`SafeLog`、`QuickActionsPanel`、
`QuickActionsPanel$1/2/3`、`MixinTouch`、`MixinMapTouchManager`、`MixinButtonTopOutliner`;以及 `PluginsCollection`。

## 合并进 APK(自行操作)

要点:不是"替换"某个 dex,而是"补丁 dex 占最前 + 原有 dex 全部顺延 +1"。

**每次合并前请先把解包目录恢复成原始状态**(从备份目录 `暮色黄昏_世界大战0.25.1._dexbak_*` 取原始 dex),
否则会叠加出多个补丁 dex。一键脚本 `<游戏根>\merge-dex.ps1`(或双击 `merge-dex.bat`):

```powershell
.\merge-dex.ps1                             # 改 GameCivs 下的 0.25.1 解包目录(推荐)
.\merge-dex.ps1 -UseApk                     # 直接改 APK(需 7-Zip,自动备份+顺延+zipalign)
```

完成后自行重新打包 / 签名 / 安装(签名与原版不同时需先卸载)。

## 已知取舍

- 框选需要"双击"这个前置动作,比双指略多一步,但全程单指、可单手操作;
- 双击窗口 200ms 略大于游戏自身的 175ms:`轻点后 200ms 内按下并按住 120ms 再拖` 会被识别为框选
  (若你习惯"点一下马上接着拖地图",可把 `DOUBLE_TAP_MS` 调小到 ~150ms);
- 框选期间单指平移地图不可用(同原生框选的行为);
- 普通双击(不按住)行为不变:仍是原生"缩放复位",不会误选;
- 长按移动与框选共用单指手势:双击的第二下不参与长按,且双指手势期间完全不参与长按;
- **按钮按住 1 秒会弹出设置面板** —— 若你习惯按住按钮停留较久,会觉得这个长按有点敏感;
  修改 `QuickActionsState.BUTTON_HOLD_MS` 即可调整(调大=更难触发;计时按游戏帧时间算,不受帧率/卡顿影响);
- 面板的触发按钮通过**运行时类名**识别(`InGame$14`),这是 APK 相关的事实:
  换个版本的 APK / 换个游戏版本,按钮编号可能变化 → 若长按不再弹面板,
  用日志中的实际类名改 `QuickActionsState.QUICK_BUTTON_CLASS` 即可(兵家必争的兼容点,已做兜底:凡 `InGame$N` 且图标为 outliner 的按钮也认)。
